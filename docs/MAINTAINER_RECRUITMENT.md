# Maintainer and Bus-Factor Plan

The current repository has one maintainer and release owner, Jewoong Moon. Documentation does not eliminate that delivery risk.

## Co-maintainer acceptance criteria

A co-maintainer must complete all of the following before receiving release permissions:

1. reproduce a tagged release from a clean environment;
2. review one SDK or pipeline change through a pull request;
3. triage one issue and document the decision;
4. demonstrate the release rollback and compromised-key procedure; and
5. accept the code of conduct, security policy, and conflict disclosure.

## Permission staging

- Contributor: issues and pull requests only
- Triage: label, reproduce, and close issues with rationale
- Maintainer: merge protected-branch changes after CI and review
- Release steward: create signed releases after checklist approval

No person receives sole unilateral control of both protected-branch merging and production deployment once a second maintainer is qualified.
